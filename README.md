# AR Location Tracking — HUAWEI AR Engine

Лабораторная 5AR: расстановка меток с привязкой к географическим координатам.
Построена на рабочем проекте ARImageTrackingHuawei (тот же стек: Kotlin, HUAWEI AR Engine, свой OpenGL-рендер, `CameraBackground`, `ObjModel`, `Gl` без изменений).

## Архитектура: два независимых модуля

```
com.example.imagetracking
├── location/                   ← модуль геозон. Нет импортов com.huawei.hiar, не знает про AR
│   ├── Poi.kt                  POI (id, имя, lat, lon, радиус, contentId), GeoFix, интерфейс ZoneListener
│   ├── GeoMath.kt              Haversine, выбор N ближайших с отсечением по расстоянию
│   ├── ZoneTracker.kt          вход/выход из зоны с гистерезисом
│   ├── PoiStorage.kt           локальная база SQLite (pois.db)
│   └── LocationManager.kt      GPS (android.location), «поставить метку здесь», nearest(), эмуляция GPS
├── ar/                         ← AR-модуль. Нет импортов android.location, не знает про GPS
│   ├── PlacementController.kt  состояния IDLE / SEARCHING / READY, подсказки; реагирует только на ZoneListener
│   ├── PlacementRenderer.kt    World Tracking: плоскости, hit-test по тапу, ARAnchor, отрисовка
│   └── ContentCatalog.kt       contentId → что рисовать
└── MainActivity.kt             единственное место, где модули соединяются:
                                locationManager.zoneListener = controller
```

Связь между модулями — один интерфейс:

```kotlin
interface ZoneListener { fun onZoneEntered(poi: Poi); fun onZoneExited(poi: Poi) }
```

## Пункты задания

| Требование | Реализация |
|---|---|
| Хранение списка POI (координаты, радиус, контент) | `Poi` + `PoiStorage` (SQLite) |
| Кнопка «поставить метку здесь», сохранение в локальную базу | `LocationManager.placeHere()` → `PoiStorage.insert()` |
| Расстояния по Haversine | `GeoMath.haversine()` |
| N ближайших в радиусе видимости (отсечение по расстоянию) | `GeoMath.nearest()` / `LocationManager.nearest()`: N = 3, радиус видимости = 200 м |
| Модуль AR не знает о GPS, реагирует на события | `PlacementController : ZoneListener` |
| Вход в зону: surface tracking + подсказка «наведите камеру на поверхность» | `onZoneEntered` → режим SEARCHING, плоскости начинают использоваться и подсвечиваться |
| Тап по найденной плоскости ставит контент активной метки | `PlacementRenderer.handleTap()`: `frame.hitTest` → `ARPlane.isPoseInPolygon` → `ARAnchor` с `contentId` метки |
| Вне зоны размещение заблокировано | в `handleTap` нет активной метки → отказ, плоскости не рисуются |
| При выходе из зоны режим размещения сбрасывается | `onZoneExited` → IDLE, подсказка скрыта |
| Уже размещённые объекты сохраняются при выходе | список `placed` не очищается и рисуется всегда |

## Как пользоваться

1. Android Studio → открыть папку → Gradle JDK 17 → Sync → Run (на Huawei с установленным HUAWEI AR Engine).
2. Дать доступ к камере и геолокации.
3. Выйти на улицу, дождаться GPS (строка статуса сверху покажет координаты и точность) и нажать **«Поставить метку здесь»**. Радиус зоны по умолчанию 20 м. Кнопка с названием контента переключает, какая ракета привяжется к новой метке.
4. Вы сразу оказываетесь в зоне новой метки: появится подсказка «Наведите камеру на поверхность». Когда плоскость найдена (она подсветится бирюзовым), тапните по ней, чтобы поставить ракету.
5. Отойдите дальше радиуса + 10 м: режим сбросится, подсказка и плоскости исчезнут, тап не поставит ничего, а уже поставленные ракеты останутся на месте.

### Проверка без прогулки: эмуляция GPS

Кнопка **⚙** открывает панель отладки: флажок «Эмуляция GPS» включает виртуальное положение, кнопки ← ↑ ↓ → двигают его на 10 м (стартовая точка: последний реальный GPS-фикс или центр Москвы). Так можно показать преподавателю вход, размещение, выход и сохранность объектов, не выходя из аудитории. «Убрать объекты» и «Удалить метки» сбрасывают состояние для повторной проверки.

## Параметры (константы)

| Что | Где | Значение |
|---|---|---|
| Радиус новой зоны | `MainActivity.DEFAULT_RADIUS_M` | 20 м |
| Гистерезис выхода | `ZoneTracker.EXIT_MARGIN_M` | 10 м (выход при d > радиус + 10) |
| N ближайших / радиус видимости | `LocationManager.NEAREST_COUNT` / `VISIBILITY_RADIUS_M` | 3 / 200 м |
| Макс. погрешность GPS для событий зон | `LocationManager.MAX_ACCURACY_M` | 50 м |
| Мин. время показа подсказки «наведите камеру» | `PlacementController.MIN_SEARCH_HINT_MS` | 1,5 с |
| Размер ракеты | `PlacementRenderer.OBJECT_SIZE_M` | 0,15 м |

## Замечания

* AR Engine не даёт отдельного переключателя «выключить поиск плоскостей» в конфигурации сессии, поэтому surface tracking «включается» логически: сессия работает в режиме World Tracking, но плоскости используются (подсвечиваются и участвуют в hit-test) только внутри зоны.
* GPS берётся из стандартного `android.location`, без Google-сервисов, поэтому работает на Huawei без GMS.
* Поставленные объекты живут, пока работает приложение: якоря AR не переживают перезапуск. Метки (POI) хранятся в базе и переживают перезапуск.
* В режиме World Tracking позы заданы в мировых координатах, поэтому, в отличие от Image Tracking, матрица вида берётся из `camera.getViewMatrix` (а не единичная).
